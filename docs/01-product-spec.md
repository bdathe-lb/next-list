| 项目 | 内容 |
| --- | --- |
| 中文名 | 下次 |
| 英文名 | NextList |

## 1. 产品定义

### 1.1 一句话定位

「下次」是一款供小团体共同收集、筛选和落实“以后一起做什么”的共享灵感清单。

### 1.2 解决的问题

灵感常散落在聊天记录、收藏夹和口头约定中，随后难以查找、无法确认其他成员是否感兴趣，也很难自然地推进到具体安排。「下次」将过程压缩为一条清晰链路：

> 创建小组 → 邀请成员 → 添加想法 → 成员表态 → 安排时间 → 标记完成

### 1.3 产品原则

1. **记录优先**：添加一个想法应在单页内完成，标题和分类之外均可稍后补充。
2. **小组优先**：内容天然属于小组，不建立公开信息流和好友关系。
3. **行动优先**：产品最终目标是把想法变成一次具体活动，而不是提高互动时长。
4. **轻讨论**：评论依附于想法，不提供独立聊天入口。
5. **低噪音**：普通表态不进入动态，也不触发推送。
6. **状态简单**：想法只有“想法、已安排、已完成”三个主状态。

### 1.4 成功指标

MVP 发布后重点观察：

- 新用户完成注册后 24 小时内创建或加入小组的比例。
- 新小组 7 天内产生第一条想法的比例。
- 想法从创建到被安排的转化率。
- 已安排活动被标记完成的比例。
- 每周有新增或状态变化的小组占活跃小组的比例。

指标用于判断流程是否有效，不在 MVP 中建设排行榜或成长体系。

## 2. 用户与权限

### 2.1 用户资料

首版使用邮箱注册和登录。用户资料只包含：

- 昵称：必填，2～20 个字符，去除首尾空格。
- 头像：可选；未上传时显示由昵称生成的默认头像。

账号能力：

- 邮箱注册。
- 邮箱登录。
- 忘记密码。
- 退出登录。
- 修改昵称和头像。

邮箱验证建议在注册后提示完成；加入小组、创建小组等写操作可要求已验证邮箱，是否强制见开发文档的待确认项。

### 2.2 小组角色

每个小组最多 10 名有效成员，包含管理员。每个小组只有一名管理员。

| 能力 | 管理员 | 普通成员 |
| --- | :---: | :---: |
| 查看小组和成员 | ✓ | ✓ |
| 修改小组名称 | ✓ | — |
| 创建邀请 | ✓ | — |
| 移除普通成员 | ✓ | — |
| 解散小组 | ✓ | — |
| 添加想法 | ✓ | ✓ |
| 编辑自己创建的想法 | ✓ | ✓ |
| 删除自己创建的想法 | ✓ | ✓ |
| 删除其他人创建的想法 | ✓ | — |
| 表态、评论 | ✓ | ✓ |
| 安排活动、更新安排 | ✓ | ✓ |
| 标记完成 | ✓ | ✓ |
| 删除自己的评论 | ✓ | ✓ |
| 删除其他人的评论 | ✓ | — |
| 退出小组 | 需先转让管理员或解散 | ✓ |

为了避免小组成为无主状态，管理员不能直接退出。MVP 支持管理员先把管理员身份转让给另一名成员；若组内仅剩管理员一人，可直接解散。

### 2.3 内容所有权

- 想法的创建者可编辑和删除自己创建的想法。
- 管理员可删除组内任意想法和评论。
- 评论发布后不支持编辑，发布者可删除自己的评论。
- 所有有效成员都可安排想法、修改安排、标记完成。
- 已完成内容在 MVP 中不能退回“想法”或“已安排”，避免产生含糊的历史状态；完成日期、照片、评价和评分仍可由有效成员修正。

## 3. 核心对象与状态

### 3.1 想法分类

固定为六类：

| 枚举 | 中文 | 建议图标 |
| --- | --- | --- |
| `place` | 地点 | 地标 |
| `restaurant` | 餐厅 | 餐具 |
| `ktv_song` | KTV 歌曲 | 麦克风 |
| `movie` | 电影 | 场记板 |
| `activity` | 活动 | 日历/旗帜 |
| `other` | 其他 | 灯泡 |

首版不支持用户自定义分类。

### 3.2 想法状态

```text
想法（idea）
  └─ 安排活动 → 已安排（scheduled）
       ├─ 修改安排 → 已安排（scheduled）
       └─ 标记完成 → 已完成（completed）
```

- “安排活动”必须填写日期和时间。
- “标记完成”默认完成日期为今天，可修改。
- 删除是独立的软删除状态，不展示为第四种业务状态。

### 3.3 两套态度的区别

想法表态用于判断“是否对这个主意感兴趣”：

- 想参加
- 都可以
- 不感兴趣

活动参加状态用于确认“是否参加这次已经确定时间的活动”：

- 参加
- 待定
- 不参加

安排活动后仍保留原想法表态。两者分别展示，不能混用。

## 4. 信息架构

### 4.1 底部导航

底部只保留三个一级入口：

1. **小组**：小组列表及所有小组内操作。
2. **动态**：与当前用户相关的重要动态。
3. **我的**：资料、通知、关于和退出登录。

添加想法、创建小组等操作在对应页面内出现，不新增第四个底部入口。

### 4.2 页面清单

```text
启动
├─ 启动页
├─ 登录
├─ 注册
└─ 忘记密码

主界面
├─ 小组
│  ├─ 小组列表
│  ├─ 创建小组
│  ├─ 输入邀请码 / 打开邀请链接
│  └─ 小组详情
│     ├─ 想法 / 已安排 / 已完成
│     ├─ 添加 / 编辑想法
│     ├─ 想法详情
│     │  ├─ 表态
│     │  ├─ 评论
│     │  ├─ 安排 / 修改安排
│     │  └─ 标记完成
│     ├─ 随机决定
│     ├─ 成员列表
│     ├─ 邀请成员
│     └─ 小组设置
├─ 动态
│  └─ 动态对应内容详情
```

## 5. 详细功能

### 5.1 启动与登录

#### 启动判断

1. 未登录：进入登录页。
2. 已登录且资料完整：进入小组列表。
3. 已登录但昵称未设置：进入完善资料页。
4. 由邀请链接唤起且未登录：先保存待处理邀请，登录成功后继续加入流程。

#### 登录页

元素：

- 应用标识“下次”与简短说明。
- 邮箱输入框。
- 密码输入框，支持显示/隐藏。
- 登录按钮。
- “忘记密码”入口。
- “注册账号”入口。

反馈：

- 邮箱格式、密码为空等在本地校验。
- 登录期间按钮显示加载并防止重复提交。
- 错误使用可理解文案，例如“邮箱或密码不正确”“网络不可用，请稍后重试”，不直接展示 Firebase 原始错误。

#### 注册页

字段：

- 昵称。
- 邮箱。
- 密码。
- 确认密码。
- 头像可在注册后补充，不阻塞注册。

注册成功后创建用户资料并进入小组列表；页面以非阻塞方式提示验证邮箱。

### 5.2 小组列表

#### 页面内容

- 顶部标题“我的小组”。
- 右上角“加入小组”。
- 右下角“创建小组”浮动按钮。
- 小组卡片按最近活跃时间倒序排列。

每张小组卡片显示：

- 小组名称。
- 最多 5 个成员头像，超出显示“+N”。
- `N 位成员`。
- `N 个想法`。
- `N 个已安排`。

统计口径：

- “想法数量”只统计状态为“想法”的未删除内容。
- “已安排数量”只统计状态为“已安排”的未删除内容。
- 已完成不计入以上两个数字。

#### 空状态

标题：“还没有小组”

说明：“创建一个小组，或使用朋友发来的邀请码加入。”

操作：“创建小组”“输入邀请码”。

### 5.3 创建、加入和退出小组

#### 创建小组

- 单字段：小组名称，必填，2～30 个字符。
- 创建者自动成为管理员。
- 创建成功进入小组详情，并引导邀请成员。

#### 邀请成员

只有管理员可创建邀请。邀请页提供：

- 分享邀请链接。
- 复制邀请码。
- 可选输入一名已注册用户的邮箱发送定向邀请。
- 显示过期时间。
- “重新生成”操作；重新生成后旧邀请立即失效。

MVP 约定：

- 邀请码不绑定特定邮箱，持有链接或邀请码的人均可申请加入。
- 邀请 7 天后过期。
- 同一小组同一时间只保留一条有效邀请。
- 小组达到 10 人后不可加入，邀请页显示“成员已满”。
- 定向邀请仅用于向已注册用户产生应用内邀请和推送，不提供用户搜索、好友推荐，也不会向未注册邮箱代发邮件。
- 为防止探测某个邮箱是否注册，发送定向邀请后统一显示“如果对方已注册，将收到邀请”。

#### 加入小组

加入确认页显示：

- 小组名称。
- 当前成员数量。
- 部分成员头像。
- “加入小组”按钮。

异常：

- 邀请无效或过期。
- 小组已解散。
- 成员已满。
- 用户已在组内：直接进入小组详情。

#### 退出和移除

- 普通成员退出前二次确认；退出后不再接收组内动态和通知，历史内容仍显示原昵称与头像快照。
- 管理员移除成员前二次确认。
- 被移除或主动退出后，其原有想法和评论保留，避免破坏历史；想法表态和活动参加状态从当前统计中移除，防止随机结果或参加人数被已退出成员影响。
- 管理员需先转让管理员或解散小组，不能让小组无管理员。

#### 解散小组

管理员输入小组名称确认。确认后：

- 小组立即对成员不可访问。
- 客户端清除该小组本地缓存。
- 服务端异步清理或归档子集合和图片。

### 5.4 小组详情

#### 顶部区域

- 小组名称。
- 成员头像组，点击进入成员列表。
- “邀请成员”图标；普通成员不可见。
- “更多设置”图标。

#### 内容标签

- 想法
- 已安排
- 已完成

默认打开“想法”。切换标签保留各自滚动位置。

#### 想法标签

- 横向分类筛选：全部、地点、餐厅、KTV 歌曲、电影、活动、其他。
- 卡片显示标题、分类、创建者、创建时间、想参加人数。
- 默认按创建时间倒序。

#### 已安排标签

- 按活动时间升序；已过时间但未完成的内容仍保留并标识“待完成”。
- 卡片显示标题、活动日期时间、集合地点、参加/待定人数。

#### 已完成标签

- 按完成日期倒序。
- 卡片显示标题、完成日期、照片缩略图和评分（如有）。
- 作为小组历史，不提供分类外的复杂筛选。

#### 通用操作

- 右下角添加想法按钮始终存在。
- “想法”标签提供“随机决定”入口。
- 下拉刷新用于重建监听或重试；正常实时更新无需手动刷新。

#### 空状态

- 想法：“还没有灵感，记下大家下次想做的事吧。”
- 已安排：“还没有安排，从想法里挑一个定下来。”
- 已完成：“完成的活动会留在这里。”
- 分类筛选无结果：“这个分类还没有想法。”

### 5.5 添加和编辑想法

在一个可滚动页面完成，不使用步骤条。

字段：

1. 标题：必填，1～80 个字符。
2. 分类：必填，六选一。
3. 备注：可选，最多 1,000 个字符。
4. 图片：可选，最多 1 张。
5. 地址或链接：可选，最多 500 个字符。

交互：

- 默认分类为“其他”，但保存前仍明确展示当前分类。
- 图片支持从相册选择和移除；MVP 不要求相机拍摄。
- 地址或链接是同一个自由输入字段。识别为 `http/https` 链接时可点击，否则按普通文本展示。
- 点击保存后立即返回详情或列表，上传中的图片显示进度。
- 如图片上传失败，保留表单内容，允许重试或移除图片后保存。
- 编辑仅更新可编辑字段，不改变创建者和创建时间。

离开未保存表单时，如果有改动，提示“放弃本次编辑？”。

### 5.6 想法详情

从上到下展示：

1. 状态和分类。
2. 标题。
3. 图片（若有）。
4. 备注。
5. 地址或链接。
6. 创建者和创建时间。
7. 想法表态。
8. 安排信息和参加状态（仅已安排/已完成）。
9. 完成记录（仅已完成）。
10. 评论列表与评论输入。

更多菜单：

- 创建者：编辑、删除。
- 管理员查看他人内容：删除。
- 其他成员：无编辑或删除入口。

主要操作随状态变化：

| 状态 | 主要操作 |
| --- | --- |
| 想法 | 安排活动 |
| 已安排 | 修改安排、标记完成 |
| 已完成 | 编辑完成记录 |

### 5.7 成员表态

未表态时显示“选择你的态度”。用户点击后可随时切换：

- 想参加
- 都可以
- 不感兴趣

每种态度显示人数。点击人数或标签打开成员底部弹层，按态度分组展示头像和昵称。未表态成员不在三类统计中，可在弹层底部显示“还有 N 人未表态”。

表态更新使用覆盖写入，每名成员每条想法只有一条当前表态。表态：

- 不创建动态。
- 不发送通知。
- 只更新计数和详情展示。

### 5.8 评论

评论区按时间正序展示：

- 评论人头像和昵称。
- 评论内容。
- 评论时间。

规则：

- 内容必填，1～500 个字符。
- 支持纯文本，不支持图片、回复层级、@、表情包和链接预览。
- 输入框固定在详情页底部或随键盘上移。
- 发布后实时出现在其他在线成员页面。
- 作者可删除自己的评论，管理员可删除任意评论；删除前二次确认。
- 评论用户自己创建的想法时，不给自己发送通知。

### 5.9 安排活动

从想法详情或随机结果进入安排页。

字段：

- 日期：必填。
- 时间：必填。
- 集合地点：可选，最多 200 个字符。
- 备注：可选，最多 500 个字符。

规则：

- 默认日期为今天之后最近可选日期，不强制活动时间必须晚于当前时间，以便补录。
- 保存后状态变为“已安排”。
- 首次安排创建一条重要动态，并向除操作者外的有效成员发送通知。
- 修改安排创建“安排已更新”动态；仅当日期或时间发生变化时再次推送。

安排完成后，成员可选择：

- 参加
- 待定
- 不参加

未选择时不计入三类人数。成员可随时修改参加状态，不创建动态、不发送通知。

活动临近通知默认在开始前 30 分钟发送。若活动在创建安排时距离开始不足 30 分钟，则不补发“即将开始”通知，避免刚安排即收到两次通知。

### 5.10 随机决定

入口位于小组“想法”标签。

筛选仅包含：

- 分类：默认全部。
- 最少感兴趣人数：默认 0；可选 0～当前成员数。

候选范围：

- 当前小组中未删除且状态为“想法”或“已安排”的内容。
- “感兴趣人数”只统计“想参加”，不包含“都可以”。

结果页显示一张突出卡片及两个操作：

- 换一个。
- 安排这个。

若抽到的内容已经安排，“安排这个”打开现有安排供成员确认或修改，不重复创建第二份安排。

算法：

1. 客户端根据筛选条件获取候选项。
2. 使用均匀随机选择一条。
3. 点击“换一个”时，在候选数大于 1 的情况下排除当前项再抽取。

无候选项时显示“没有符合条件的想法”，提供“调整条件”和“添加想法”。

### 5.11 标记完成

字段：

- 完成日期：必填，默认今天。
- 照片：可选，最多 1 张。
- 简短评价：可选，最多 500 个字符。
- 评分：可选，1～5 星，仅支持整数。

保存后：

- 状态变为“已完成”。
- 内容进入“已完成”列表。
- 创建“小组完成了一项活动”动态。
- 不要求所有参加成员确认。

完成记录代表小组共同记录，不是每人独立评分。所有有效成员均可修改完成记录；页面展示最后修改人和时间。

### 5.12 动态

动态只保留高价值事件：

- 某人添加了新想法。
- 某条想法被安排或关键时间被更新。
- 某人评论了当前用户创建的想法。
- 某项活动被标记完成。
- 当前用户收到一条定向小组邀请。

不显示：

- 普通想法表态。
- 活动参加状态。
- 用户浏览行为。
- 普通资料修改。

动态卡片显示：

- 事件图标。
- 一句事件描述。
- 小组名称。
- 事件时间。
- 未读标记。

排序为时间倒序。点击后进入对应小组或想法详情，并标记已读。列表顶部提供“全部标记已读”。目标内容已删除时，点击后显示轻提示并将动态置为已读。

动态是“与当前用户相关”的个人收件箱：

- 添加、安排、完成事件发送给组内所有其他有效成员。
- 评论事件仅发送给想法创建者，且评论者不是创建者本人。
- 定向邀请事件只发送给被邀请的已注册用户。
- 操作者本人的动作不进入自己的动态。

MVP 仅保留最近 90 天动态，服务端可定期清理。

### 5.13 我的

页面内容：

- 头像和昵称，点击进入编辑资料。
- 当前邮箱，只读展示。
- 通知设置。
- 关于应用。
- 退出登录。

通知设置按类型提供开关：

- 小组邀请。
- 新安排活动。
- 活动即将开始。
- 自己创建的想法收到评论。

系统通知权限关闭时，页面顶部说明并提供进入系统设置的入口。应用内动态与推送通知相互独立：关闭推送不影响动态记录。

“关于应用”显示应用名称、版本号、隐私政策和开源许可入口。隐私政策正文及账号注销流程需在正式发布前补齐。

## 6. 通知文案

| 类型 | 标题示例 | 正文示例 | 点击目标 |
| --- | --- | --- | --- |
| 小组邀请 | 邀请你加入「周末去哪」 | 打开下次，看看大家想一起做什么 | 加入确认页 |
| 新安排 | 新活动已安排 | 「去植物园」安排在 7 月 26 日 14:00 | 想法详情 |

通知正文不得展示评论全文，避免在锁屏泄露敏感信息。

## 7. 视觉与交互规范

### 7.1 视觉方向

- 简洁、现代、浅色、温和、有生活感。
- 不使用大面积粉色、爱心、情侣专属文案。
- 以中性暖白背景、低饱和绿色主色、少量暖橙强调建立生活感。
- 分类通过图标和小面积色块识别，不让颜色承担唯一语义。

### 7.2 建议设计令牌

最终颜色需在无障碍对比度检查后确定，以下作为设计起点：

| 用途 | 建议值 |
| --- | --- |
| Primary | `#426B5A` |
| On Primary | `#FFFFFF` |
| Primary Container | `#D9E9E0` |
| Secondary | `#8A674A` |
| Accent | `#E89A5B` |
| Background | `#FAF9F6` |
| Surface | `#FFFFFF` |
| Text Primary | `#20231F` |
| Text Secondary | `#666B65` |
| Outline | `#D9DDD8` |
| Error | `#BA1A1A` |

界面采用 Material 3 体系：

- 圆角：卡片 16dp，输入框 12dp，标签 999dp。
- 间距：以 4dp 为基础，常用 8/12/16/24/32dp。
- 卡片优先使用边框和轻微色差，不依赖重阴影。
- 正文最小 14sp，主要标题 22～28sp。
- 触控区域不小于 48dp。

### 7.3 动效

- 列表新增和状态切换使用短时淡入/位移动效。
- 随机决定可有 400～600ms 的轻量洗牌动效，但结果应立即可访问。
- 不使用会阻碍操作的长动画。
- 遵循系统“移除动画”设置。

### 7.4 无障碍

- 正文与背景对比度至少达到 WCAG AA。
- 所有图标按钮提供内容描述。
- 头像、分类和状态不能只靠颜色区分。
- 支持系统字体缩放，关键操作在 200% 字体下仍可使用。
- 时间、人数和星级提供适合 TalkBack 的完整描述。

## 8. 全局体验规则

### 8.1 加载

- 首屏用骨架屏或进度指示，不显示空白页。
- 写操作使用局部加载，避免锁住整个页面。
- Firestore 本地缓存可先显示旧数据，同时展示轻量同步状态。

### 8.2 离线

- 已缓存的小组和内容可只读浏览。
- 添加评论、表态和文本想法可进入 Firestore 离线队列。
- 图片上传、创建/加入/退出小组等服务端事务要求联网。
- 离线写入在页面显示“等待同步”；失败后提供重试。

### 8.3 错误

错误分三类：

- 可重试：网络、超时、临时服务错误。
- 需修正：字段校验、成员已满、邀请码过期。
- 权限变化：被移除、小组解散、内容删除；应退出当前页面并说明原因。

不要直接向用户展示异常堆栈、Firestore 路径或 Firebase 错误码。

### 8.4 防重复

- 保存按钮提交后立即禁用。
- 创建、加入、安排、完成等关键服务端操作支持幂等。
- 深链重复打开时不重复加入或创建动态。

## 9. 埋点建议

首版仅采集产品漏斗所需事件，且不上传评论、备注等用户内容：

- `sign_up_completed`
- `group_created`
- `group_joined`
- `idea_created`（仅带分类）
- `idea_reaction_set`（仅带态度类型）
- `idea_scheduled`
- `schedule_rsvp_set`
- `random_used`（仅带候选数量和筛选项）
- `idea_completed`

属性不得包含邮箱、昵称、标题、地址、链接或评论正文。

## 10. MVP 验收标准

### 10.1 账号

- 用户可用邮箱完成注册、登录、重置密码和退出登录。
- 用户可修改昵称与头像。
- 未登录用户不能读取任何小组业务数据。

### 10.2 小组

- 用户可创建小组并成为管理员。
- 管理员可生成邀请，其他用户可通过链接或邀请码加入。
- 第 11 名用户加入时被明确拒绝。
- 成员可加入多个小组。
- 权限矩阵中的管理与成员操作均受到服务端规则保护，而不是只隐藏按钮。

### 10.3 想法与实时同步

- 成员可在一个页面创建包含必填项和任意可选项的想法。
- 两台已登录设备打开同一小组时，一方新增或修改想法，另一方无需刷新即可看到更新。
- 状态只会在规定路径间变化。
- 分类筛选和三标签列表结果正确。

### 10.4 表态和评论

- 每名成员每条想法最多保留一条当前表态。
- 三种表态人数与成员明细一致。
- 评论可实时同步，且仅想法创建者收到评论动态/通知。
- 普通表态不产生动态或通知。

### 10.5 安排、随机和完成

- 安排必须包含日期和时间，保存后进入“已安排”。
- 活动参加状态与想法表态独立。
- 随机结果只来自满足分类和最少“想参加”人数、且尚未完成的内容。
- 完成记录保存后进入历史列表，照片和评分均可留空。

### 10.6 通知

- 仅四类允许通知能够产生推送。
- 用户关闭某类通知后不再收到该类推送。
- 点击通知可进入正确目标；目标已失效时应用不会崩溃。

## 11. 待产品确认项

以下选择不会阻塞文档评审，但编码前应确定：

1. 是否强制完成邮箱验证后才能创建或加入小组。建议强制，以降低滥用。
2. 管理员转让是否进入 MVP。本文按“进入 MVP”设计，否则管理员只能解散，体验较差。
3. 活动临近提醒提前量是否固定 30 分钟。本文按固定值设计。
4. 是否允许补录过去时间的安排。本文允许，便于补记活动。
5. 软删除内容是否需要 30 天恢复入口。本文仅保留服务端软删除，不提供用户恢复界面。

## 12. 非目标

MVP 不实现好友、私聊、群聊、公开社区、地图探索、AI 推荐、费用分摊、独立投票、视频上传、排行榜、积分、会员支付、广告、Web 或 iOS。

评论、表态和参加状态都服务于把想法变成活动，不扩展为社交关系或项目管理系统。
